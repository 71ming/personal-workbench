# 个人工作台 · 桌面版（Tauri 2）

把现有的「Node 服务 + 浏览器」形态，换成一个**双击图标就能开、不弹黑色命令行窗口**的桌面软件。

**当前状态：阶段 1 全部完成。** 阶段 0（路线验证）+ 阶段 1（笔记/任务/收藏/网页抓取）
都已编译、实测通过、出过安装包。**笔记、任务、收藏的功能与 Node 版完全一致。**

剩下的：移动端（需要 macOS + Xcode）、AI 问答（需要密钥）、导入 Node 版的现有数据。

---

## 这个版本的目的

**只验证一件事：Tauri 这条路走得通吗？**

具体是验证三个假设：

1. 现有的 `public/index.html`（176KB）能不能**一行不改**就在 Tauri 窗口里跑起来
2. Rust 版的 SQLite 数据层能不能替代 `server.js`
3. 真实安装包到底多大、启动多快

功能上**只做了笔记**（新建 / 编辑 / 自动保存 / 搜索 / 软删除 / 导出），
任务和收藏的接口先返回空数组 —— 让界面能完整显示、不报红横幅而已，
它们的逻辑要等这一关过了再平移。

> 为什么要分阶段：`server.js` 有 71KB，一次性全量平移的话，
> 出问题时你分不清是「Tauri 本身不行」还是「某一块 Rust 写错了」。
> 拆开之后每一步都能定位。

## tauri.conf.json 的几处「为什么不那么写」

> ⚠️ **这个文件里放不了注释**。Tauri 用严格 JSON 解析它，
> 写 `//` 注释会直接报 `key must be a string`（而且行号指向注释处，很难一眼看懂）。
> 所以下面这些说明都记在这里，不写进配置文件。

| 配置 | 值 | 为什么 |
|---|---|---|
| `build.frontendDist` | `../../public` | 直接指现有的 `public/`，不用复制一份。相对 `src-tauri/` 往上两级正好是它 |
| `app.security.csp` | `null` | 不是疏忽。窗口加载的是 `http://127.0.0.1`，页面里有大量内联 `<style>`/`<script>`（零构建的单文件前端），收紧 CSP 会全部拦掉、白屏。真实攻击面（用户粘进来的链接）在 Rust 侧的 `is_private_host` / `norm_url` 上拦，不依赖 CSP |
| `windows[0]` 不配 `url` | —— | 配了窗口会先加载那个地址、然后 Rust 再 `navigate` 过去，白白多一次失败请求，还可能看到一闪而过的白屏。真实地址在 `lib.rs` 里运行时决定 |
| `bundle.windows.nsis.installMode` | `currentUser` | 默认装到 Program Files 要管理员权限。个人工具用当前用户安装，省得每次弹 UAC |
| `app.withGlobalTauri` | `false` | 不把 Tauri API 挂到 `window.__TAURI__`。这个应用的前端完全不需要它，暴露出来只会多一条攻击面 |

## capabilities/default.json 为什么只有一条权限

Tauri 2 新增的「权限声明」明确规定前端 JS 能调用哪些系统能力。
这里只给了 `core:default`（最基础的一组），因为界面完全不需要碰文件系统、
剪贴板、注册表——所有事情都由 Rust 后端做，前端只发 HTTP 请求。

保持权限最小化有实际意义：将来万一出现 XSS，攻击者能调用的系统能力也是有限的。
这跟「别让一条异常路径捅到整个系统」是同一个思路。

所以「零依赖」的真正成本不是仓库大小，是**部署门槛**——现在换成了

`Cargo.toml` 里开了体积优化（`opt-level="z"` + `lto` + `strip`）才到这个数。

> NSIS 是 Windows 主流格式而且能用「当前用户」模式装（不用管理员权限），
> 所以不影响使用。暂时只出 NSIS，`targets` 里那个 `"msi"` 待查清原因后再决定去留。

## 实测踩到的坑（阶段 0 ~ 1c）

这十七条全是真踩的，不是预防性提醒。

### 1. `tauri.conf.json` 里放不了注释

写 `//` 注释会报 `key must be a string`，而且**行号指向注释那一行**，看错误信息完全想不到是注释的问题（JSON 里 `//` 在字符串内部是合法的）。

规矩：配置文件保持纯 JSON，所有「为什么这么写」记在这份 README 里。

### 2. 路由切路径段时，`api` 那一段要先去掉

```rust
// ❌ "/api/notes" → trim_matches('/') → "api/notes" → split → ["api","notes"]
//    seg[0] 是 "api"，拿它比 "notes" 永远比不上
let seg: Vec<&str> = path.trim_matches('/').split('/').collect();

// ✅
let seg: Vec<&str> = path.trim_start_matches("/api/").trim_matches('/').split('/').collect();
```

这个 bug 烦人的地方：服务是活的、端口是通的、JSON 正常返回，
只是内容永远是 `no such endpoint`。看起来「像那么回事」，不是崩了。

**是逐条打接口打出来的，不是读代码读出来的。**

### 3. rusqlite 要求「参数个数」和「占位符个数」完全一致

```rust
// ❌ 无搜索那条 SQL 里一个占位符都没有，却照样传了一个参数
// → error: Wrong number of parameters passed to query. Got 1, needed 0
query_map([&pattern], ...)

// ✅ 无占位符就传空数组
query_map([], ...)
```

别图省事合并两条 SQL（`(?1 IS NULL OR title LIKE ?1 ...)`），
分开写更好读。

### 4. 判断「这条还在不在」要看受影响行数，不能「更新完再读回来」

```rust
// ❌ SQL 里有 AND deleted_at IS NULL，已删除的记录其实改了 0 行（拒绝得完全正确）
//    但 get_note 不过滤 deleted_at，会把那条记录原样返回 —— 看起来像更新成功了
conn.execute(sql, params![..])?;
get_note(conn, id)

// ✅ execute 返回的是实际改动的行数
let changed = conn.execute(sql, params![..])?;
if changed == 0 { return Ok(None); }   // 前端转成 404
```

SQL 写得对、返回的 JSON 也有模有样，只有真去删一条再改它才会暴露。

### 5. Windows 上两个进程可以同时 bind 同一个端口

这是实测撞上的：用户的 `server.js`（node）和 `workbench` 同时占着 8787，
**两边都 bind 成功、都不报错**，但谁来处理请求变得不确定。

所以不能依赖 bind 报错。正确做法是**先用 `TcpListener` 探一下**：

```rust
match TcpListener::bind(&addr) {
    Ok(probe) => drop(probe),          // 探完就还回去
    Err(e) => return Err(format!("端口 {} 被别的程序占着……", port)),
}
```

中间有一瞬间空档存在竞态，但这个进程本来就在启动阶段，概率小到可忽略。

### 6. 端口固定 8787，不能用随机端口

`localStorage` 按 origin（协议+主机+端口）隔离，而前端用它存 Markdown 视图模式：

```js
let mode = localStorage.getItem('wb-mode') || 'edit';
```

端口每次启动都变 = 每次都是新 origin = 这个偏好设置**每次启动都白存**。
而这个 bug 极难发现：界面完全正常，只有一个偏好悄悄失效。

（代价是 8787 被占时不能自动换端口，所以同时加了 `WORKBENCH_PORT` 环境变量，
需要并跑时手动指定。）

### 7. release 版不能回退到「构建机的源码路径」找资源

第 6 条那个「先资源目录、再源码树」的写法，在开发时很好用，但实测拷到临时目录
单独跑 exe 时发现：**服务起来了、接口也通，看起来完全正常**——
因为 `CARGO_MANIFEST_DIR` 是**编译期常量**，构建机的路径已经写死在 exe 里了，
而这台机器上那个路径确实还在。

拷到别人电脑上，那条路径必然不存在，界面直接白屏；程序不崩、没有日志，
极难判断问题在哪。

改成按构建类型区分：

```rust
if cfg!(debug_assertions) {
    // 只有开发构建才回退到源码树（改了前端刷新就生效）
    return Ok(dev_path);
}
Err("找不到界面文件 public/index.html。重新安装一次应该就好……")
```

**发布版找不到就明确报错**，不要悄悄回退到一个在目标机器上必然失效的路径。
「把『明确找不到』变成『莫名其妙白屏』」是最坏的一种降级。

### 8. 「双击闪一下就没了」——发布版没有控制台，等于错误信息全丢

用户装完双击，窗口开一下就关，什么提示都没有。

**根因是一条链**：

1. `tauri.conf.json` 的 `frontendDist` 指向 `../../public`
2. 但**编译时 Tauri 并不会把 public/ 复制到 target/ 目录里**
   —— `frontendDist` 只对 `cargo tauri build` 打的**安装包**有意义
3. 所以直接跑 `target/release/workbench.exe` 时，
   `resource_dir()` 指向 `target/release`，那儿根本没有 `public/index.html`
4. → 报错退出 → 而 release 故意设了 `windows_subsystem = "windows"`（没有控制台）
   → **错误信息唯一的去处就是空气** → 用户只看到闪一下

**两个错误叠在一起**，而且单独任何一个都不致命：
「找不到资源」本来是能弹窗告诉用户的，
「没有控制台」本来是为了体验好。
凑一起就成了「出错了却不让用户知道怎么修」——这比出错更糟。

**修法一：出错必须留下痕迹。**
所有启动失败都写 `app_data_dir\启动错误.log`，并且**当场打开**它。
用系统自带记事本而不是弹窗，是为了不加 `winapi` 或 `tauri-plugin-dialog` 依赖。

⚠️ 写日志**必须带 UTF-8 BOM**：不带的话记事本按系统 ANSI（中文 Windows 是 GBK）读，
满屏「涓汉宸ヤ綔鍙」。这跟坑「启动.bat 必须 UTF-8 BOM」是同一个坑的另一个方向——
那边是 cmd 不看 `chcp`，这边是记事本不看编码标记。

**修法二：根本不要依赖外部文件。**
把界面用 `include_bytes!` 编译进 exe，逻辑是「磁盘上有就用磁盘的，没有就用内嵌的」：

- 开发时：磁盘上有 `public/`，改完 index.html 刷新窗口就生效，不用重编译
- 发布时：磁盘上没有（或被杀毒软件删了），用内嵌的那份，**一定能开**

代价是改 index.html 会让 cargo 重编本 crate（debug 约 8 秒）。可以接受。

### 9. `TcpListener::bind` 成功 **不等于** 端口是空的

第一个版本判断「端口被占用」用的是：试着 `bind` 一下，失败就是被占。

**实测证明这个判断是错的**：8787 已经被 node（server.js）占着时，
`TcpListener::bind("127.0.0.1:8787")` **依然返回成功**。
Windows 的 socket 默认可复用地址，两个进程可以同时 bind 同一端口且都不报错，
谁处理请求变得不确定（谁先 accept 谁接）。

**正确做法是「连一下试试」**：能不能连上，才是真的有人在用那个端口。
这个判断不受 `SO_REUSEADDR` 影响 —— 端口上有活着的服务就一定连得上。

> 通用教训：**「我抢占成功」不能证明「那里没人」**。
> 想判断资源是否被占用，要用「能不能碰到对方」，不是「我能不能占下」。

### 10. 诊断开关写反了，差点得出错误结论

为了能在有控制台的 debug 环境里复现发布版行为，加了个 `WORKBENCH_STRICT_RESOURCES=1`
的开关，本意是「设了就别回退到源码树」。

结果判断写反了 —— 变量叫 `strict`，条件却是「允许回退」。
于是设了 `=1` 反而回退，诊断显示「一切正常」，
我差点据此在提交信息里写下「资源查找没问题」。

**判断反了的标志：一开诊断开关，故障就消失了。**
诊断开关本身出 bug 时，它的表现和「问题已修复」一模一样。
以后写这类开关，先确认「开关**关掉**时行为和原来完全一致」。

### 11. `setup` 返回 `Err`，Tauri 内部还会再 panic 一次

上面那条修完优雅退出后，**退出码还是 -1073740791**（panic）。

原来以为是这样：setup 返回 Err → `run()` 返回 Err → 外层 `if let Err` 接住 → 优雅退出。
结果外层那个分支**压根没机会执行** —— Tauri 收到 setup 的 Err 之后内部自己 panic 了。

改法很直接：**报告完直接在 setup 里 `std::process::exit(1)`，不把错误返回给 Tauri。**

代价是那种「Tauri 自己内部的启动失败」不再被上报（比如窗口创建失败），
但那种情况本来也会 panic，用户看到「已停止工作」，区别不大。

**顺序很重要：先把错误说明摆到用户眼前（写日志 + 打开），再退出。**
Windows 那个「XX 已停止工作」的红框是**模态对话框**，
会盖住刚打开的记事本——用户先看到红框，合理地推断「这软件崩了」，
根本不会去看旁边那篇写清楚了该怎么办的日志。

**用不上的排查手段就别留在代码里**：先前那版把「优雅退出」写在 `run()` 外面，
看着更「规整」，实际上永远执行不到。`#[warn(unused variable)]` 已经提示过。

### 12. 平移接口时，改「更合理」就等于制造 bug

两个后端要同时存在，用户会来回切。行为差一点点就会变成玄学 bug ——
同一个请求在旧版能搜到、新版搜不到，没人说得清为什么。

所以平移时是**照抄契约，不是照着更合理的样子重写**。这轮核对出来必须一致的地方：

| 行为 | server.js | Rust 版 |
|---|---|---|
| 空标题 | `未命名任务` / 笔记 `无标题` | 一样 |
| 假日期 `2026-13-45` | **原样存**（正则只看形状，不校验真实日期） | 一样 |
| 非数字 id | 400 `{error:'bad id'}` | 一样 |
| `status` 白名单 | 只有 `done` 其余全当 `todo` | 一样 |
| 更新是否局部更新 | 否，三个字段一起存 | 一样 |

唯一有意加的差异：Rust 版返回里**多了 `deleted_at`**。恢复删除要用，
且多一个只读字段不影响前端。

> 第一轮就是在这栽的：我看到 Rust 版对 `2026-13-45` 判为「非法日期」，
> 就去「修」它，结果改坏了一个本来就该原样保留的行为。
> **先读旧实现，再动手。**

### 13. 测试红了，先怀疑测试

`test-tasks.js` 首轮 34 项红了 5 项，查下来只有 1 项是真差异，另外 4 项全是测试自己写错：

- 手写的 `%E5%B9%BF%E9%80%8F` **根本不是「逾期」的编码**（解出来是另一个词），
  中文搜索因此永远搜不到 —— 却一度以为是 percent decode 没实现
- 排序断言在「标记完成」**之前**就检查「已完成排最后」，而那一刻它还是待办
- 断言里写了两个同名任务去对 4 元素数组，实际只有一个
- 拿 `2026-13-45` 当非法日期用例（就是第 12 条那个）

规矩：
- **URL 里的中文一律用 `encodeURIComponent()` 生成**，不要手写 `%XX`。
  手写的转义和 Node/Python 算出来的经常差一个字节，测出来是接口的锅。
- 断言写完先在纸上推一遍它应该长什么样，再拿去跑。
- 判断方法：把期望值和实现**都**读一遍，看它俩是不是本来就不该一样。
- **测试数据要隔离**。用固定关键词（`待删除的收藏`）的话，测第二轮就会搜出
  第一轮恢复回来的那条，「搜不到」这条会假红。关键词带上时间戳。
- **中文用例不是可选的**，见下面第 14 条 —— 这个项目的用户就中文，
  只测 ASCII 等于没测。

### 14. Rust 切字符串的中间，会在中文上 panic

收藏接口第一轮 43 项里挂了 15 项，最后揪出来是一个字符的错：
我写 `s[..7]` 来剥 `http://`，但 `http://` 是 7 字符、`https://` 是 8 字符，
同一个下标切两边，https 的链接全被当成「冒号后面是空的」而拒掉。

修完又栽一次：改成 `&t[..7]` 之后，**导出会 500**：

```
thread '<unnamed>' panicked at src\db.rs:677:24:
end byte index 7 is not a char boundary; it is inside '己' (bytes 6..9 of string)
```

Rust 的 `&str` 是 UTF-8，切片必须落在**字符边界**上。
而导出时要把每个标题拿去和协议头比对 —— 只要用户起过一个中文标题，
`&t[..7]` 就切在「己」字中间，直接 panic。

同一个项目里这个坑一共出现了**四个地方**：`strip_scheme`、`strip_www`、
`format_due_cn`、`norm_due`。四处都是「先 `len()` 判断长度，再按下标切」。

通用改法：**判断和切片都用 bytes，不碰字符串本身**。

```rust
// 错的：len() 数的是字节，10 字节的中文串能混过去
if d.len() != 10 { return d.to_string(); }
let m = &d[5..7];          // ← 这里 panic

// 对的：先确认 4、7 两个位置确实是 ASCII 短横，
// 那几个切点就必然是字符边界
let b = d.as_bytes();
if b.len() != 10 || b[4] != b'-' || b[7] != b'-' { return d.to_string(); }
let m = &d[5..7];          // ← 安全
```

要点：
- **`str::len()` 返回字节数，不是字符数。** 拿它当「长度对不对」的判据，
  中文一定漏。
- `s[a..b]` 里的 `a`/`b` 必须是字符边界。用 `bytes()` 检查前置条件，
  别直接切。
- 抽出来复用（`strip_scheme()`）不只是为了少写代码 ——
  **同一个魔法数字在四处各写一遍，就是四处可能各错一遍。**

`test-bookmarks.js` 里那组中文标题用例就是钉死这件事的，别删。

### 15. 「小写版字符串」传进会被改的函数，下标全错位

抓取第一版正文提取失败，症状是「标题抓对了，正文只剩半句」：

```
实际 = "e in documentation examples."     ← 少了 "This domain is for us"
```

根因：我把 `html.to_ascii_lowercase()` 算好一次，然后传进
`drop_block(s, lower, tag)`，指望两个字符串等长、按字节对齐。

但 `body` **每删掉一个块长度就变了**：

```rust
for tag in DROP_BLOCKS {
    body = drop_block(&body, &lower, tag);   // ← lower 还是原始 html 的
}
```

第一轮 `body` 变短了，`lower` 没变，后面所有 `find` 出来的下标
对应到的是另一个位置，于是从中间开始乱切。

改法很简单，但值得记：

```rust
// 错的：小写版由调用方传，和 s 不同步
fn drop_block(s: &str, lower: &str, tag: &str) -> String

// 对的：要什么自己算，保证和 s 永远同步
fn drop_block(s: &str, tag: &str) -> String {
    let lower = s.to_ascii_lowercase();
    ...
}
```

**通用教训**：如果一个函数会**修改**传入的字符串，
那么任何「为它预先算好的辅助数据」（小写版、长度、索引表）
都不能从外面传 —— 一定在里面现算。
「症状是内容被截断/错位」几乎都指向这一类问题。

### 16. 只匹配 `<div>` 等于一条都没匹配

同一个文件的另一个 bug：正文挤成一坨，没有换行。

第一版 `replace_tags` 匹配的是精确的 `<div>`、`</div>`。
但真实页面里写的是 `<div class="content">`、
`<div id="main" data-x="1">` —— **属性部分是随便什么**。
精确匹配的结果就是零命中，一个标签都没换掉。

改成：找到 `<`，读到 `>`，取中间那段，取**第一个空白或 `/` 之前的部分**当标签名。

```rust
let name = inner.split(|c: char| c.is_whitespace() || c == '/' || c == '>')
               .next().unwrap_or("");
if tags.contains(&name) { /* 换成换行 */ }
```

**通用教训**：处理 HTML/XML/命令行参数这类**带属性的标签**，
「精确字符串匹配」几乎总是错的。
（真实页面里 `<div>` 裸标签的占比其实很小。）

### 17. IPv6 的「地址里全是冒号」会破坏按冒号切端口的逻辑

`hostname_of("https://[::1]:8080/x")` 第一版返回 `::1]:8080`。

安全判断全靠这个函数切出来的名字，而这个错切出来的字符串
**不等于** `::1`，所以 `is_private_host` 放行了 —— 
「切得难看」在这里不是显示问题，是**拦不住 ::1**。

第一版用 `rfind(':')` 去端口，但 IPv6 地址本身全是冒号。
改成：先看有没有 `[`，有就在第一个 `]` 处截断。

所以补了一条测试，不是测「切得对不对」，而是直接测**拦不拦得住**：

```rust
#[test]
fn 切出来的名字仍然拦得住() {
    // 主机名切错在这里不是「切得难看」，是「拦不住 ::1」
    for u in ["http://[::1]:8080/", "http://127.0.0.1:8787/api/notes", ...] {
        assert!(is_private_host(hostname_of(u)));
    }
}
```

**通用教训**：安全相关的函数，测试要**测最终效果**，不要测中间步骤。
「`hostname_of` 返回什么」是实现细节，「这个地址拦不拦得住」才是需求。
实现改了中间步骤是常事，效果不能变。

## 阶段 1c：网页抓取（已完成并实测通过）

这是整个应用里**唯一一处「用户给个地址、我替他去访问」的功能**，
所以安全要求比别的接口高得多。代码在 `src-tauri/src/fetch.rs`。

```powershell
node desktop\tools\test-fetch.js http://127.0.0.1:8795
```

**46 项断言全过**，其中 24 条是内网拦截（12 个攻击地址 × 2 项）。
另有 8 项 Rust 单元测试（`cargo test`）。

### 一道都不能少的拦截

| 拦截 | 为什么 |
|---|---|
| 只放行 http/https | `javascript:` 存进来点一下就是代码执行 |
| **拦内网地址** | 见下 |
| **每跳重定向重验一次** | 见下 |
| 8 秒超时 | 界面不能无限转圈 |
| 2MB 体积上限 | 不是为了内存（2MB 撑不死谁），是别把十万字长文存进库 |
| Content-Type 校验 | 别把一个 200MB 的安装包读进内存 |
| 不存 cookie | 存了等于在你数据库里存网站凭据 |
| 登录墙识别 | 抓到登录框不算成功，否则标题变成「登录 XXX」比不抓还糟 |

**为什么必须拦内网**：这个服务会替用户访问任意网址。粘一条
`http://127.0.0.1:8787/api/notes` 就能让它把自己的数据库读出来；
`http://169.254.169.254/` 还能碰到云主机的元数据接口（能拿到访问密钥）。
单机小工具也一样要拦 —— 否则「贴个链接」就等于开了一条内网通道。

**为什么每跳重定向都要重验**（最容易省、也最要命的一条）：
用户粘一个正常的外网地址，那个站把你 302 到 `169.254.169.254`，
你照样乖乖请求过去。**只在入口查一次是不够的。**
所以 reqwest 关掉了自动重定向（`Policy::none()`），自己手动跟，最多 5 跳，
每一跳开头都重做一遍全部检查。选 reqwest 而不是 ureq 就是为了这个 ——
ureq 默认自动跟，中间地址看不见，没地方插检查。

实测拦住并确认「内容为空」的地址：

```
127.0.0.1:8795/api/notes        读工作台自己的笔记
localhost:8795/api/export       导出工作台数据库
169.254.169.254/                云主机元数据（含密钥）
192.168.1.1/  10.0.0.5/  172.16.0.1/
0.0.0.0  127.1.2.3             回环的各种写法
[::1]:8795  [fd00::1]  [fe80::1]   IPv6 内网
```

### 为什么用 blocking 而不是 async

reqwest 正常是 async 的，而这个服务端（tiny_http）和数据层（rusqlite）
都是同步的。要用 async 版就得把整个服务改成异步 —— 加运行时、
把数据层全包进 async、换掉 tiny_http。

**没这么做，理由写在这**：抓取最多 8 秒，这 8 秒里唯一会来的请求
就是用户点的那个「重新抓取」本身。为一个人本地用的应用引入异步运行时，
是拿架构整洁换实际收益为零的东西。

代价是一个**已知限制**，写在 `http_server.rs` 的注释里了：
`incoming_requests()` 是串行的，抓取期间其它请求会排队等它。
实际影响很小（顶多自动保存晚几秒落库，不会丢）。
什么时候该改：真要做「后台批量抓取」或「多窗口同时用」的时候 ——
那时正确做法是抓取丢进后台线程 + 轮询状态，不是简单地开线程。

### HTML 解析：为什么不加解析器

`fetch.rs` 里的正文提取全是手写字符串处理。加一个 HTML 解析 crate
能拿到的无非是更准一点的边界处理，而这个功能是「锦上添花」——
抓回来的正文本来就要给人读，不是给程序解析。为了 100KB 依赖
去赌一堆正则的边界情况，不划算。

**已知能力缺失**：Rust 没有内建 GBK 解码器（那是另一个 crate），
所以还停留在 GBK/GB2312 的老站点会显示乱码。这是**有意识接受的**：
解不出中文不会崩，也不会把数据弄坏 —— 原文总比没有强。

### 测试数据会堆积，记得清

三个测试脚本都往同一个库里塞数据，跑几轮能堆到一百多条，
会干扰人工验证。清：

```powershell
node desktop\tools\clean-test-data.js http://127.0.0.1:8795
```

只删指向 `example.com` / `example.org` / `iana.org` 的，
以及标题叫「攻击测试」的 —— 不会碰你自己存的收藏。
